# Портал сервисов rep.local.inion — фронтенд

Одностраничное приложение на React 19. Это главная страница `https://rep.local.inion/`, с которой сотрудники переходят в NetBox, MediaWiki и другие системы.
Папка `dist/` уже собрана: её можно сразу положить на сервер (раздел 9 ТЗ).

## Возможности

| Раздел | Что умеет |
|---|---|
| **Каталог систем** | Сводка (сколько систем, сколько доступно, средний отклик, доступность), поиск, фильтры по категориям и статусу, сортировка, вид «плитка» или «таблица», избранное |
| **Карточка системы** | Иконка и цвет, описание, теги, статус с индикатором, история последних проверок, время ответа, % доступности, меню действий |
| **Добавление и правка** | Форма с проверкой полей: обязательные поля, формат маршрута, повторы названий и адресов. Есть выбор иконки (20 шт.) и цвета (8 шт.), теги, ответственный, отдельный адрес для проверки доступности, открытие в новой вкладке |
| **Удаление** | Спрашивает подтверждение. В течение 8 секунд удаление можно отменить из уведомления |
| **Мониторинг** | Проверка шлюза Nginx (`/health`) и каждой системы, карта маршрутов домена, таблица с откликом, средним временем, доступностью и графиком. Автопроверка раз в 30 с, 1 мин или 5 мин |
| **Журнал действий** | Записывает добавление, изменение (с перечнем изменённых полей), удаление, импорт и смену статусов. Есть поиск, фильтр и выгрузка в CSV (открывается в Excel) |
| **Настройки** | Тёмная, светлая или системная тема, отключение анимаций, интервал проверки, экспорт и импорт каталога в JSON, сброс |
| **Удобство** | `Ctrl+K` — быстрый переход к системам и командам, `/` — поиск, `N` — добавить систему. Интерфейс адаптирован под телефон, работает с клавиатуры, учитывает `prefers-reduced-motion` |

Внешних запросов у портала нет: шрифты системные, иконки встроены, CDN не используется. Поэтому он полностью работает в закрытой сети.

## Развёртывание на сервере

```bash
# 1. Скопировать проект (достаточно dist/, nginx.conf, Dockerfile, docker-compose.yml)
scp -r dist nginx.conf Dockerfile docker-compose.yml root@rep.local.inion:/opt/services/portal/

# 2. Собрать и запустить контейнер
cd /opt/services/portal
docker compose up -d --build

# 3. Проверить
curl -I https://rep.local.inion/
```

По сравнению с ТЗ в `nginx.conf` внесены три изменения:
- `config.js` и `index.html` не кешируются, иначе новая версия портала или новые настройки дошли бы до пользователей только через 30 дней;
- файлы из `/assets/` имеют хеш в имени, поэтому кешируются на год;
- добавлены `server_tokens off` и заголовок `X-Content-Type-Options`.

## Настройки без пересборки — `dist/config.js`

```js
window.PORTAL_CONFIG = {
  domain: 'rep.local.inion',
  title: 'Портал сервисов',
  organization: 'Корпоративная инфраструктура',
  apiBase: null,            // '/api' — общий каталог на сервере
  gatewayHealthUrl: '/health',
  healthInterval: 60,       // секунд, 0 — без автопроверки
  slowThresholdMs: 1500,    // ответ дольше — статус «Медленно»
  supportContact: 'admin@local.inion',
  demo: false,              // true — статусы имитируются (для показа вне сервера)
};
```

`docker-compose.yml` монтирует этот файл в контейнер. Чтобы изменения вступили в силу, достаточно отредактировать файл и обновить страницу в браузере.

## Где хранится каталог

**По умолчанию (`apiBase: null`)** каталог хранится в `localStorage` браузера. Это закрывает требование ТЗ «добавлять и удалять системы через веб-интерфейс» без серверной части. Ограничение: каждый пользователь видит собственный список. Первый раз у всех показываются NetBox и Вики.

**Общий каталог для всех сотрудников.** Укажите `apiBase: '/api'` и поднимите любой небольшой сервис, который реализует такой контракт:

| Метод | Путь | Тело / ответ |
|---|---|---|
| GET | `/api/systems` | → `PortalSystem[]` |
| POST | `/api/systems` | `PortalSystem` → `PortalSystem` |
| PUT | `/api/systems/:id` | `PortalSystem` → `PortalSystem` |
| DELETE | `/api/systems/:id` | → 204 |
| PUT | `/api/systems` | `PortalSystem[]` — замена списка (импорт, сброс) |

```ts
interface PortalSystem {
  id: string; name: string; url: string;          // url: '/netbox/' или 'https://…'
  description?: string; category?: string; owner?: string; tags?: string[];
  icon: string; accent: string;                    // см. src/components/Icon.jsx и src/lib/defaults.js
  healthUrl?: string; newTab?: boolean; pinned?: boolean;
  createdAt: string; updatedAt: string;            // ISO 8601
}
```

Файл, полученный кнопкой «Экспорт» в настройках, имеет нужный формат: его удобно использовать как начальные данные для API.

## Как работает мониторинг

Доступность систем проверяет браузер пользователя, пока портал открыт.
- Для маршрутов на том же домене (`/netbox/`, `/wiki/`) портал читает настоящий HTTP-код. Если Nginx отвечает 502, 503 или 504, значит, контейнер лежит, и система помечается недоступной. Коды 2xx, 3xx и 4xx (включая страницу входа) означают, что система работает.
- Для внешних адресов браузер может определить только, пришёл ли ответ (режим `no-cors`).
- Если ответ пришёл дольше `slowThresholdMs`, статус — «Медленно».

## Сборка из исходников

Нужен Node.js 18 или новее.

```bash
npm install
npm run build     # → dist/
npm run dev       # сервер разработки с пересборкой: http://localhost:5173
```

Сборщик — esbuild (`build.mjs`). Он быстрый, у него одна зависимость, а итоговые JS и CSS получают хеш в имени.

## Добавление новой системы (раздел 13 ТЗ)

1. Поднимите контейнер и добавьте `location` в `/etc/nginx/conf.d/rep.local.inion.conf`.
2. На портале нажмите «Добавить» (или клавишу `N`), укажите название и маршрут, например `/grafana/`.
3. После сохранения портал напомнит проверить маршрут в Nginx, и система сразу попадёт под мониторинг.
